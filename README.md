# Ambifo CRM v1

A modern rebuild of the Ambifo Cloud CRM. Three-tier architecture:

| Tier    | Tech                                  | Role                                                            |
| ------- | ------------------------------------- | ---------------------------------------------------------------- |
| Frontend | React 19 · Vite 8 · TypeScript · Tailwind CSS v4 | Attractive animated UI for customers, leads, and dashboard (Ambifo brand theme) |
| Backend  | Python 3.13 · FastAPI · SQLAlchemy 2 · Pydantic 2 | REST API, authentication, and owns the PostgreSQL schema         |
| Engine   | Rust (Axum) · tokio · tinytemplate   | Heavy compute: templating, email queue, AI orchestration, CSV parsing, PDF/DOCX generation, Mermaid diagrams |

Delivers full feature parity with the legacy Flask CRM (`ambifo-cms`), with a fresh "Rust-first" database schema.

## Features

- **Auth** — JWT login (HS256) with an auto-seeded default admin account
- **Customers** — full opportunity profile (cloud operator, segment, deal status, AWS/Opp ID, billing, comments), search, segment/status filtering
- **Customer history** — tagged timeline entries (note, call, meeting, email, bulk status, update)
- **Leads** — funnel with `new` → `contacted` → `qualified` → `converted`/`lost`, inline status changes, one-click convert to customer
- **Financials** — expected/actual MRR + ARR and credit buckets per customer
- **Dashboard** — KPI cards, deal-status/segment breakdowns, opportunities-over-time bars, recent activity feed
- **Email** — template CRUD (auto-seeded `welcome` + `demo_followup`), engine-rendered previews (`{{macro}}`), send + queue via Rust engine, per-log records
- **CSV import** — analyze any CSV via the Rust engine, then bulk-import into Customers or Leads with smart header mapping (spaces/hyphens → snake_case) or an explicit `column_map`
- **Documents** — SOW generation via the Rust engine (stored with history), plus generic document upload / storage / download per customer
- **Diagrams** — Mermaid flowcharts generated by the Rust engine (entities list or AI-generated definition), stored per customer
- **AI** — proxy to the Rust AI orchestrator (OpenAI chat completions or Gemini generateContent)
- **Rust engine** — fully wired: `/health`, template rendering, CSV parsing, email queue, SOW/PDF generation, Mermaid diagrams, AI calls

## Prerequisites

- Node.js 22.12+ (Vite 8 requirement), npm
- Python 3.13
- Rust 1.8x (edition 2024)
- PostgreSQL 16 running locally as a service

## Setup

### 1. Database

```sql
CREATE ROLE crm_app LOGIN PASSWORD 'StrongPassword123';
CREATE DATABASE ambifo_crm_v1 OWNER crm_app;
```

Tables are created automatically by FastAPI on startup (`Base.metadata.create_all`).

### 2. Backend (FastAPI)

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
copy .env.example .env          # edit variables
```

`DATABASE_URL` should point at the v1 database, e.g.:

```
postgresql+psycopg2://crm_app:StrongPassword123@localhost:5432/ambifo_crm_v1
```

Start the API:

```bash
python run.py                   # http://127.0.0.1:8000   (or: uvicorn app.main:app --reload)
```

Interactive docs at <http://127.0.0.1:8000/docs>.

### 3. Engine (Rust)

```bash
cd backend/engine
cargo build
cargo run                       # http://127.0.0.1:8081
```

### 4. Frontend (React)

```bash
cd frontend
npm install
npm run dev                     # http://localhost:5173
```

Sign in with the default admin (created on first startup): **admin / admin123**
(change `DEFAULT_ADMIN_USERNAME` / `DEFAULT_ADMIN_PASSWORD` in `backend/.env`).

## API surface

FastAPI docs at <http://127.0.0.1:8000/docs> once running. Highlight endpoints (all JWT-protected):

| Area | Endpoints |
| --- | --- |
| Auth | `POST /api/auth/login`, `GET /api/auth/me` |
| Admin | `GET/POST /api/admin/users`, `PUT/DELETE /api/admin/users/{id}`, `POST /api/admin/users/reset-all-passwords` |
| Customers | `GET/POST /api/customers`, `GET/PUT/DELETE /api/customers/{id}`, `PUT /api/customers/bulk/update`, `GET/POST /api/customers/{id}/history`, `GET/PUT /api/customers/{id}/financials`, `GET /api/lookups` |
| Leads | `GET/POST /api/leads`, `PUT/DELETE /api/leads/{id}`, `POST /api/leads/{id}/convert` |
| Dashboard | `GET /api/dashboard` |
| Email | `GET/POST /api/email/templates`, `PUT/DELETE /api/email/templates/{id}`, `POST /api/email/render`, `POST /api/email/send`, `GET /api/email/logs`, `GET /api/email/logs/{log_id}`, `POST /api/email/bulk` (all customers/leads, by status/segment, manual list), `POST /api/email/bulk/retry-failed` |
| Import | `POST /api/import/csv-analyze`, `POST /api/import/customers`, `POST /api/import/leads` |
| Documents | `POST /api/documents/sow/generate`, `GET /api/documents/sows`, `GET /api/documents/sows/{id}`, `POST/GET /api/documents` (upload/list), `GET /api/documents/{id}` (download) |
| Diagrams | `POST /api/diagrams/generate`, `GET /api/diagrams`, `GET/DELETE /api/diagrams/{id}` |
| AI | `POST /api/ai/generate` (OpenAI or Gemini via engine) |
| Health | `GET /health`, `GET /engine/health`, `GET http://127.0.0.1:8081/health` |

## Verification

- API health: `GET http://127.0.0.1:8000/health` → `{"status":"ok"}`
- Engine health: `GET http://127.0.0.1:8081/health` → `{"status":"ok"}`
- Engine ↔ API bridge: `GET http://127.0.0.1:8000/engine/health`
